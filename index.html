Overview What the analyzer does and how your data is handled

The LRCCD Student Prerequisite Analyzer organizes copied Class Roster and prerequisite checker data into a clear view of each student's prerequisite completion. Results can be reviewed in the browser and exported as XLSX, CSV, or ODS files.

Prerequisites are the official requirements for the class. Indirect Evidence comes from the LRCCD Indirect Prerequisite Checker. When that evidence matches an official prerequisite or its official former course number, it can satisfy that prerequisite. Other indirect-only courses are shown for context and do not affect prerequisite status.

Student data stays local. Roster and prerequisite information is processed in your browser and is not sent to or stored on an external server.

Step-by-Step Instructions Show detailed directions for using the analyzer
  1. If you believe there is any data in the textboxes below, click Reset Roster or Reset All Fields in the Student Prerequisite Analyzer to clear existing data before proceeding.
  2. Log into the Los Rios Intranet (opens in a new tab).
  3. Select Online Grade Reporting and Class Rosters and click Go to Service.
  4. Select the desired roster and click Get Roster.
  5. Activate the page and copy its contents (Ctrl + A, Ctrl + C on Windows or Cmd + A, Cmd + C on Mac).
  6. Paste the copied data (Ctrl + V on Windows or Cmd + V on Mac) into the Roster Data textbox.

Start with the roster. Roster Data must be accepted before prerequisite or indirect checker data can be processed.

  1. Choose whether you want to check Prerequisites, Indirect Evidence, or both.
  2. Back in the LRCCD roster, click on the Prereq Checker link.
  3. Activate the page and copy its contents (Ctrl + A, Ctrl + C on Windows or Cmd + A, Cmd + C on Mac).
  4. Paste the copied data (Ctrl + V on Windows or Cmd + V on Mac) into the Prerequisite Data textbox.
  5. If you also want to review indirect evidence, click the Indirect Prereq Checker link on the Prerequisite Checker page.
  6. Activate the page and copy its contents (Ctrl + A, Ctrl + C on Windows or Cmd + A, Cmd + C on Mac).
  7. Paste the copied data (Ctrl + V on Windows or Cmd + V on Mac) into the Indirect Evidence Data textbox.
  8. Click Process Data to view your organized student data.
  9. Use the class summary and filters to focus on students who are complete, missing prerequisites, or have Indirect Evidence.
  10. Select View for a student to see how each prerequisite was satisfied and any additional Indirect Evidence. Students missing prerequisites also have an editable Copy Message option.
  11. If you would like to save your data for later, scroll down to the Download section.
  12. Select your preferred file format from the dropdown menu.
  13. Click Download to save your processed data.

Support Diagnostics Create a privacy-safe report for technical problems

If you are reporting a technical problem that cannot be reproduced locally, open Support Diagnostics, copy or download the report, and include it with your email.

The report is designed to help troubleshoot browser, service-worker, cache, and application-state problems without including student records.

What the Report Contains See what Support Diagnostics includes and excludes

Included

  • Application version and expected cache information.
  • Browser, platform, language, viewport, and display information.
  • Service-worker registration and cache state.
  • Privacy-safe workflow state such as whether roster or prerequisite data was accepted and whether the Faculty or Admin source format was detected.
  • Recent privacy-safe diagnostic events.

Not Included

  • Pasted roster or prerequisite text.
  • Student names or student IDs.
  • Course or professor information.
  • Prerequisite records or result-table contents.

Why This Exists How a personal spreadsheet became a faculty web application

The LRCCD Student Prerequisite Analyzer began as a spreadsheet I created to make prerequisite tabulation easier for my own courses. As I revised that process for my own use, I started thinking about the faculty in my department doing the same work. At that point the question became broader: if my faculty needed a better way to work with this information, other faculty across LRCCD probably did too.

A spreadsheet was not the right solution for broader use. I also did not have access to a district application server, and any solution handling student-record information needed to protect that data. The analyzer was therefore built as a browser-based application that processes roster and prerequisite information locally rather than transmitting student data to an external server.

About the LRCCD Student Prerequisite Analyzer Purpose, design, and privacy

The LRCCD Student Prerequisite Analyzer is a client-side faculty and staff utility for organizing Class Roster, Prerequisite Checker, and Indirect Prerequisite Checker data into a single prerequisite-completion view.

The application supports separate Faculty and Admin source formats, reconciles current and official former course numbers, keeps indirect-only evidence separate from official prerequisite status, and provides browser results, student detail, editable Copy Message tools, and spreadsheet exports.

All roster and prerequisite processing occurs locally in the browser. The application does not require a server-side student database and does not transmit pasted student data to an external server.

3.0.0-dev

  • Rebuilt roster, Prerequisite Checker, and Indirect Prerequisite Checker parsing around separate Faculty and Admin source formats.
  • Added fail-closed parser behavior so unrecognized LRCCD structure is not mistaken for valid empty prerequisite data.
  • Recognized Prerequisite Checker pages with no listed courses now ask the user to confirm the valid empty result instead of blocking the workflow.
  • Added Common Course Numbering support, including values such as STAT C1000, and safer handling of unsupported prerequisite course blocks.
  • Current and former course numbers are preserved together in output headers, and official former numbers reconcile legacy Indirect headings without creating duplicate prerequisite columns.
  • Only official prerequisite columns affect student status. Indirect-only courses are labeled as Indirect Evidence, remain informational, and do not count for or against the student.
  • Added sanitized regression tests and a unified parser test dashboard.
  • Replaced paste timing delays with direct clipboard capture.
  • Improved keyboard and dialog accessibility.
  • Escaped LRCCD-derived values before inserting them into generated HTML or dialog markup.
  • Improved PWA cache isolation and development-build identification.
  • Refreshed the interface with a wider workspace, card-based data entry, compact status badges, clearer results hierarchy, and stronger separation between prerequisites and indirect evidence.
  • Added an explicit per-student results status so users can quickly see whether all official prerequisites are complete or how many remain missing.
  • Added a compact class summary and filters for All, Complete, Missing Prerequisites, and Has Indirect Evidence.
  • Added per-student detail views showing each prerequisite, whether it is missing or complete, and whether completion is listed in the Prerequisite Checker or supported by Indirect Prerequisite Checker evidence.
  • Added an editable per-student Copy Message for students missing official prerequisites. Indirect-only evidence is never presented as a missing prerequisite.
  • Added a privacy-safe Support Diagnostics page that captures browser, PWA/cache, application-state, and recent event information without including student or pasted LRCCD data.
  • Streamlined support and feedback to email, with Support Diagnostics available when a problem cannot be reproduced locally.
  • Standardized faculty-facing language around Prerequisites and Indirect Evidence, clarified when Indirect Prerequisite Checker evidence can satisfy a prerequisite, and simplified student-detail explanations.
  • Centralized per-student result calculations in a shared results model used by the table, filters, student detail, Copy Message workflow, and spreadsheet exports.
  • Expanded regression coverage to include the results model, Copy Message generation, submission workflow rules, and diagnostics privacy safeguards.
  • Consolidated startup notices onto the shared accessible dialog system and hardened unexpected application-error reporting for Support Diagnostics.
  • Centralized runtime version, build, and cache metadata to reduce release-maintenance drift.
  • Added wide-table support with horizontal scrolling, sticky Student ID and Student Name columns, and overflow-aware scroll controls for classes with many prerequisite columns.
  • Reorganized the interface around Home, Support, and About. Home keeps the analyzer workflow as the main view with an expanded Overview and collapsed Step-by-Step Instructions, while Support and About use collapsible sections for secondary information.
  • Added the same official prerequisite status to XLSX, CSV, and ODS exports for consistency with the browser results.
  • When Indirect Evidence is selected but left empty, users with valid prerequisite data can explicitly continue without it. Pasted Indirect data that fails parsing still requires review.
  • Updated the startup system-status notice to reflect the current Version 3 development build and remaining release testing.
